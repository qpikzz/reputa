# STMT-002 — Расчёт скоринга по выписке

## Дата
Актуализировано 2026-09-07.

## Статус
Выполнено.

## Описание
Расчёт вклада банковской выписки в итоговую оценку заёмщика на основе среднего
остатка, регулярности поступлений и доли трат на обязательные/необязательные
категории. Формирует часть позитивных сигналов / факторов риска в `ScoreResult`.

## Что сделано
Модуль `backend/app/scoring/stmt_scoring.py`:
- `calculate_statement_features(statement)` — извлечение признаков из распарсенной
  выписки (`ParsedBankStatement` из STMT-001):
  - `cashflow_ratio` — отношение доходов к расходам;
  - `essential_ratio` — доля трат на базовые нужды (продукты, ЖКХ, здоровье, транспорт);
  - `discretionary_ratio` — доля трат на кафе/шоппинг;
  - `num_incomes`, `avg_income_interval`, `income_interval_std` — частота и
    регулярность поступлений;
  - `cushion_ratio` — подушка безопасности (остаток / среднемесячный расход).
- `calculate_score_from_features(feats)` — единая формула начисления баллов
  (базовые 50, модификаторы −25…+20 по пяти блокам, clamp 0–100) + сигналы/риски +
  метрики портрета 0–10 + текст отчёта для комитета.
- `score_statement(statement)` — конвейер признаков → итоговый результат.
  Возвращает `StatementScoringResult` (score, сигналы, риски, три метрики портрета,
  отчёт) — та же структура, что у `TelegramScoringResult` из TG-002, что позволяет
  объединять их в TG-003.

## Интеграция
`score_statement` вызывается из `POST /applications` (APP-002) внутри
`calculate_final_profile` (TG-003) как «выписочная» часть итоговой оценки (вес 0.7).
Работает и в отсутствие telegram-данных — тогда итоговая оценка = 100% по выписке.
