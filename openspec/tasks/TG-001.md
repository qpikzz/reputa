# TG-001 — Парсинг публичного Telegram-канала

## Статус
Выполнено.

## Описание
Модуль получения сообщений публичного Telegram-канала по адресу, указанному в заявке (`Application.telegram_channel`): извлекает username, скачивает страницу канала и разбирает её на структурированный список сообщений (текст + дата).

## Принятое решение
Сообщения читаются через **публичную web-preview-страницу `https://t.me/s/<username>`**, а не через Telegram Bot API.

Причина: Bot API (`getChat`/`getUpdates`) отдаёт сообщения только каналов, в которые бот добавлен как участник. Для произвольного публичного канала из заявки это не сработает без ручной вставки бота в каждый канал. `t.me/s/<username>` отдаёт ~20 последних сообщений любого публичного канала без токена и членства — адекватный источник для MVP. Решение согласуется с «Откатом» из PLAN.md: если источник недоступен — telegram-сигнал просто не участвует в оценке.

Модуль:
- `parse_channel_username(channel)` — достаёт username из `@user`, `t.me/user`, `t.me/s/user`, `telegram.me/user`, голого имени; `None` для приватного invite-link (`t.me/+...`), не-ASCII и невалидных имён.
- `parse_channel_page(body, username)` — чистый разбор HTML web-preview (без сети): посты по `tgme_widget_message_wrap`, текст — из `js-message_text` (ссылкам оставляется их текст, `<br>` превращается в перенос строки, HTML-сущности раскодируются), дата — из `<time datetime="...">`; фото — из CSS `background-image` фотоблоков (`photo_urls`). Посты без текста, но с фото включаются в результат (см. TG-002 — их анализирует OCR); пропускаются только посты без текста и без фото.
- `fetch_channel_messages(channel)` — «username → скачать → разобрать»; любая ошибка (приватный/удалённый канал, сетевая ошибка, невалидный username) возвращает `None`, а не бросает исключение — основной сценарий не блокируется.

## Затронутые файлы
- `backend/app/schemas/telegram.py` — `TelegramMessage`, `ParsedTelegramChannel`.
- `backend/app/scoring/telegram_channel.py` — вся логика (новый модуль, без новых зависимостей: `urllib` из stdlib). Позже (в рамках TG-002) добавлено извлечение `photo_urls` и включение фото-постов без подписи.
- `backend/tests/test_telegram_channel.py` — 30 тестов (с учётом добавленных в TG-002): username-парсинг (валидные/невалидные форматы), разбор HTML-страницы (реальный срез разметки t.me/s), пропуск медиа-постов без текста и фото, извлечение фото-URL, пустая страница, макет сетевого запроса, сетевые ошибки → `None`, невалидный/приватный адрес → `None` без обращения в сеть.

## Проверка
- `python -m pytest` в `backend/` — 234 passed (23 новых по TG-001).
- Реальный запуск: `fetch_channel_messages("https://t.me/s/durov")` → 20 сообщений с текстом и датой (`datetime` с UTC-смещением).
- Приватный/несуществующий канал и сетевые ошибки → `None`, исключений нет.
- `parse_channel_username` распознаёт: `@channel`, `https://t.me/channel`, `t.me/s/channel`, `telegram.me/my_channel`, голое имя; отклоняет invite-link `t.me/+...`, не-ASCII и короткие/цифровые имена.

## Что осталось
- Интеграция в итоговую оценку: `TG-002` (расчёт скоринга и психологического портрета по сообщениям) и `TG-003` (объединение telegram-сигнала с оценкой по выписке). TG-001 готов как автономный модуль.
- При необходимости ужесточить: чтение через Bot API с реальным токеном (нужна вставка бота в каждый канал) — за пределами MVP.
