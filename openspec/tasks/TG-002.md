# TG-002 — Расчёт скоринга и психологического портрета по данным канала

## Статус
Выполнено.

## Описание
Модуль расчёта оценки и психологического портрета по данным публичного Telegram-канала (`ParsedTelegramChannel` из TG-001). Два пути анализа текста: **словарные эвристики** (fallback, без внешних API) и **LLM-анализ GigaChat** (Сбер) — с NER денежных переводов. Фото распознаются отдельно через Gemini (OCR).

## Принятое решение
Telegram-оценка возвращается **отдельным** результатом `TelegramScoringResult`, а не записывается напрямую в `ScoreResult` — объединение telegram-сигнала с оценкой по выписке делает TG-003. Это соответствует декомпозиции из PLAN.md и не мешает TG-003 решать, как комбинировать сигналы.

**Единая формула.** Скоринг-логика вынесена в `_score_from_evidence(channel, evidence)`: доказательства (`work_hits`, `fin_hits`, `pos_hits`, `debt_hits`, `gambling_hits`, `has_money_transfer`, `transfers_summary`) подставляются в одну формулу независимо от источника — словарного или LLM. Пути:
- `score_telegram(channel)` — **словарные эвристики** (`_heuristic_evidence`), работает без внешних API;
- `score_telegram_with_llm(channel)` — **GigaChat** (`telegram_llm.analyze_channel_semantics`): при недоступности LLM (нет ключа, сетевая/API-ошибка, невалидный JSON) откатывается на `score_telegram()` — поведение не ломается.

Модуль (`backend/app/scoring/telegram_scoring.py`):
- `score_telegram(channel)` — основная функция: корпус из текстов сообщений, подсчёт плотности упоминаний по пяти лексическим словарям.
  - Работа/занятость (работа, проект, клиент, заказ, дедлайн, фриланс…) — `≥2 встреч` и плотность `> 0.005` → `+15` и сигнал «Упоминания трудовой деятельности или проектов.».
  - Финансовая грамотность (инвестиции, бюджет, накопления, дивиденды…) — аналогично → `+10` и сигнал «Финансовая осведомлённость…».
  - Позитивная лексика (отлично, успех, благодарю…) — `≥2 встреч` → `+5` и сигнал «Позитивный характер публикаций.».
  - Риски долгов (кредит, долг, задолженность, микрозайм, коллектор…) — `≥1` → `−15` и фактор риска «Упоминание кредитных обязательств или задолженностей.».
  - Риски азарта/спама (казино, ставки, слоты, «быстрый доход»…) — `≥1` → `−20` и фактор риска «Признаки азартной активности или спам-контента.».
- Метрики портрета (0–10), считаются только по telegram-данным:
  - `stability_score` — упоминания работы (+5) + регулярность постов по датам сообщений (+5 × `_post_regularity_score`).
  - `financial_literacy_score` — финансовая лексика (+5) + отсутствие рисковой лексики (+5; при `≥2` упоминаниях долгов/азарта −2).
  - `responsibility_score` — среднее стабильности и финграмотности, минус число факторов риска.
- `score_contribution` — базовые 50 с модификаторами (clamp 0–100).
- `report_content` — текст отчёта для кредитного комитета: статистика канала + список сигналов/рисков.

## Граничные случаи
- Пустой канал или только сообщения без текста → `score_contribution = 50`, все метрики = 5, отчёт «Недостаточно текстовых данных для анализа канала.».
- Канал с 1 сообщением → регулярность постов = 0 (нет пар дат), стабильность считается только по лексике.
- Канал недоступен (TG-001 → `None`) → `score_telegram` не вызывается, обработка отсутствия сигнала — в TG-003.

## Затронутые файлы
- `backend/app/scoring/telegram_scoring.py` — единая формула `_score_from_evidence` + словарные эвристики `_heuristic_evidence`/`score_telegram` (numpy уже в зависимостях).
- `backend/tests/test_telegram_scoring.py` — 30 тестов: пустой канал, заработок, финансовая лексика, денежные поступления («перевод + сумма»), позитив, риски (долги/азарт), нейтральный канал, границы метрик 0–10, регулярность постов, отчёт, вспомогательные функции.
- `backend/app/scoring/telegram_vision.py` — **OCR-модуль (Gemini)**: скачивание фото поста, распознавание через `gemini-3.6-flash`, добавление текста к корпусу. Без `GEMINI_API_KEY`, при сетевой ошибке или ошибке API — «красиво деградирует» (канал без изменений).
- `backend/app/scoring/telegram_llm.py` — **LLM-модуль (GigaChat)**: семантический анализ корпуса + NER переводов (`direction: income/expense/transfer`), откат на эвристики. Нечёткое сопоставление ключей JSON (устойчивость к опечаткам модели, напр. «finance_ments») и фильтр расходов — проигрыш/оплата не усиливает сигнал «денежные поступления».
- `backend/tests/test_telegram_llm.py` — 22 теста с фейковым клиентом (без сети/API): разбор JSON, нечёткие ключи, направление переводов, откаты на эвристики (нет ключа, ошибка API, не-JSON), пустой канал.
- `backend/app/schemas/telegram.py` — `TelegramMessage.photo_urls`.
- `backend/app/scoring/telegram_channel.py` — извлечение `photo_urls` из CSS `background-image` фотоблоков; **фото-посты без подписи больше не выбрасываются** (раньше TG-001 их пропускал) — теперь они включаются в анализ для OCR. Пропускаются только посты без текста и без фото.
- `backend/tests/test_telegram_vision.py` — 7 тестов с фейковой OCR-функцией и моком скачивания (без сети и API).
- `backend/tests/test_telegram_channel.py` — +3 теста извлечения фото-URL (действующие ссылки, scheme-relative, пустой список).
- `backend/app/core/config.py` — `GEMINI_API_KEY`; `GIGACHAT_CREDENTIALS` (Authorization Key), `GIGACHAT_MODEL` (GigaChat-2), `GIGACHAT_SCOPE` (GIGACHAT_API_PERS), `GIGACHAT_BASE_URL` (`https://api.giga.chat/v1`), `GIGACHAT_VERIFY_SSL_CERTS` (False — официальные примеры SDK; для prod — корневой сертификат НУЦ Минцифры).
- `backend/.env` / `.env.example` — ключ Gemini и Authorization Key GigaChat (в `.env`; в репозиторий не попадает).
- `backend/requirements.txt` — `google-genai==2.22.0`, `gigachat==0.2.3`.

## Проверка
- `venv/Scripts/python.exe -m pytest tests/test_telegram_scoring.py tests/test_telegram_channel.py tests/test_telegram_vision.py tests/test_telegram_llm.py` — 86 passed.
- Живой вызов `t.me/durov`: 20 постов (3 с фото) → `enrich_channel_with_ocr` распознал фото через Gemini → `score_telegram`.
- Живой вызов `t.me/dbndjs` (5 постов, 2 фото + пост «Короче вчера в казике минуснулся на 12.000 руб.»):
  - Эвристики: score 70, рисков нет (словарь «казино» не ловит сленг «казике»);
  - **GigaChat**: поймал азартный риск («казике», −20), извлёк переводы с направлениями (30 000 ₽ перевод, 4 490 ₽ перевод, −12 000 ₽ расход/казино) → score 50, риск «Признаки азартной активности…», отчёт с «Распознанные переводы… (расходы: …)»;
  - расход −12 000 ₽ не засчитан как «денежные поступления» (фильтр расходов).
- Полный набор: `python -m pytest` — 302 passed (4 предшествующих сбоя в `test_applications.py` не связаны с TG-002).

## Что осталось
- `TG-003` — интеграция telegram-сигнала в итоговую оценку (объединение с выпиской; работа и без telegram-данных). В pipeline TG-003, при наличии фото, вызывается `enrich_channel_with_ocr()` перед `score_telegram()`; LLM-путь — через `score_telegram_with_llm()`.
- Модель Gemini в коде `gemini-3.6-flash`; модель GigaChat — `GigaChat-2` (доступны также `GigaChat-2-Max/Pro`, `GigaChat-3-*`). При смене тарифа обновить константы.
