# TG-003 — Интеграция telegram-сигнала в итоговую оценку

## Дата
2026-09-07.

## Статус
Выполнено.

## Описание
Объединение telegram-сигнала (TG-002) с оценкой по банковской выписке (STMT-002)
в единый итоговый балл и единый `ScoreResult`. Работает и при отсутствии
telegram-сигнала: в этом случае итоговая оценка равна оценке по выписке на 100%.

## Принятое решение (архитектурное)
**Источник «выписочной» части — `stmt_scoring.score_statement` (эвристики STMT-002),
а не модель машинного обучения из `model_training.py`.**

Обоснование:
- Модель RandomForest/train из `model_training.py` обучалась на синтетических данных,
  сгенерированных **той же** функцией `calculate_score_from_features` (эвристика),
  то есть ML-модель лишь предсказывала выход эвристики — независимого сигнала она
  не добавляла, а добавляла хрупкость (пиклы-артефакты, зависимость от numpy и
  синтетического датасета).
- `score_statement` уже используется в production-пути `POST /applications`,
  покрыт сквозными тестами и не требует `model_training`/`artifacts`.
- Следствие: `model_training.py` и `backend/artifacts/*.pkl` удалены как мёртвый код.

## Что сделано
`backend/app/scoring/final_scoring.py` (переписан):
- Сигнатура `calculate_final_profile(stmt_result, tg_result=None)`:
  - `stmt_result` — `StatementScoringResult` из STMT-002;
  - `tg_result` — `TelegramScoringResult` из TG-002 либо `None`.
- Формула: `final_score = round(stmt_score * 0.7 + tg_score_contribution * 0.3)`,
  clamp 0–100 (`_WEIGHT_STMT = 0.7`, `_WEIGHT_TG = 0.3`).
- Без `tg_result` (или при недоступном/пустом канале) возвращается `stmt_result`
  без изменений — оценка на 100% по выписке, заявка не блокируется (правило TG-001).
- Метрики портрета (стабильность/финграмотность/ответственность) усредняются между
  выпиской и telegram; `report_content` — конкатенация отчётов обоих источников;
  `positive_signals`/`risk_factors` объединяются.
- Убраны: `process_raw_application` (мёртвый код), импорты `model_training`/`numpy`
  и баг с опечаткой `model_predsiction` из старой сигнатуры.

`backend/app/routers/applications.py` (`POST /applications`, APP-002):
- После создания заявки: `stmt_result = score_statement(parsed_statement)`.
- Если передан `telegram_channel`: `fetch_channel_messages` (TG-001) → при наличии
  сообщений `enrich_channel_with_ocr` (TG-002, OCR) → `score_telegram_with_llm`
  (TG-002, GigaChat с откатом на эвристики) → `tg_result`.
- `score_result = calculate_final_profile(stmt_result, tg_result)` → сохраняется
  `ScoreResult` → `apply_auto_decision` (APP-003) → `commit`.

## Граничные случаи
- Канал недоступен (fetch = `None`) → `tg_result` не вызывается, итог = 100% stmt.
- Канал доступен, но `messages == []` → `tg_result = None`, итог = 100% stmt.
- `telegram_channel` пуст/не передан → telegram-функции не вызываются вовсе.

## Затронутые файлы
- `backend/app/scoring/final_scoring.py` — переписан (формула 70/30, объединение).
- `backend/app/routers/applications.py` — вызов `calculate_final_profile` в
  `create_application` (ранее telegram-пайплайн нигде не подключался).
- `backend/tests/test_tg003_integration.py` — новые интеграционные тесты (5):
  канал доступен → 80·0.7 + 75·0.3 = 78.5 → 78; канал недоступен → 80; пустой канал

  починена генерация `id` в тестовом `_mock_db.flush` (теперь строковый
  `generate_application_id`, как в инфраструктуре).
- Удалены как мёртвый код: `backend/app/scoring/model_training.py`,
  `backend/artifacts/*.pkl`.
